# Cache bytes from allocation history

`Heap.observe_cache_stores` now generates native tcache controls, safe-linked
next pointers, keys and key-clearing stores while the existing logical heap
replays allocations and frees. This extends the
[earlier contact/cache allocation history](CAP_PRELUDE.md) toward removing
captured raw cache bytes at via entry.

The initial allocator metadata and process tcache key are explicit inputs.
The observer writes cache bytes from those inputs and subsequent operations;
it does not initialize them from later raw byte snapshots. It refuses
incomplete initial chains rather than inventing a valid tail or count.
The same new-mapping zero initialization and released-range invalidation used
by the byte-backed mode also apply while observing stores.

## Continuous handoff to byte reads

During this pre-via phase, allocation decisions still use the logical lists.
`attach_cache_memory` can then enable actual reads of the generated bytes
without reinitializing their counts, heads, links or keys. The handoff must
keep the same memory object and process key. Attempting to restart observation
after backing/tracing is rejected.

After the handoff, subsequent guest writes to cached links remain observable.
The test deliberately damages a next pointer and verifies the byte-backed
reader reports the unmapped link rather than restoring the old logical list.
This preserves the earlier [shared-memory corruption behavior](SHARED_MEMORY.md).

This observer is for the phase before an out-of-range numerical stamp can
corrupt allocator bytes. It does not claim arbitrary byte-corruption handling
while still using logical decisions. Other arena metadata remains logical;
the production trailing-via guard remains enabled.

## Complete original comparison

`audit_cache_stores_original.py` starts with the contact-entry allocator state,
generates the initial cache bytes, and uses the same heap and memory through
the contact/cache prelude and subsequent matrix/workspace lifetimes. Contact,
conductor, filament, via and clone counts come from Python geometry. No cache
bytes are reset at CAP matrix entry or via entry.

The comparison uses the existing immutable original fixture and all 65
selected histories in cold and warm states. Expected raw cache bytes are read
only by the comparator. All original outcomes and the later node fault remain
present; no fixture is replaced or selected case omitted.

At contact entry, CAP matrix entry and via entry, it exactly matches:

- **130 cases and 390 boundaries**.
- **47,304 raw 32-bit cache words**, including every control word and the two
  user words of every currently cached chunk.
- **16,764 allocation/free events and 8,902 allocation addresses** through
  those boundaries.
- The existing logical allocator state, mappings and parameters.

There are zero differences in CPython and packaged Pyodide/WebAssembly.
The mandatory `prelude` WASM suite runs the four cache-store tests alongside the existing contact/cache and
contact-storage tests, followed by the full regenerated-matrix comparison.
The earlier storage, heap/mapping, numerical and JOIN/UNJOIN gates remain
required and unchanged.

## Remaining integration

The [complete CAP buffers](CAP_STORAGE.md), contact records and these cache
stores now have independently verified producers. They still need to be
replayed together with subsequent numerical/allocator stores in the same
memory before raw via-entry heap inputs can be removed. Earlier process,
scene and cache-table history, non-cache allocator bytes, numerical workspaces
and repeated command cleanup remain unfinished. Known logarithm/cosine and
JOIN/UNJOIN discrepancies also remain; these component matches do not establish
complete original-binary parity or make this development branch deployable.
