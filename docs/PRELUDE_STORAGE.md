# Numerical and file-buffer bytes before CAP

`prelude_storage.py` now generates all grid FFT scratch arrays and binary
stream buffers freed between contact preparation and the first CAP matrix
allocation. These stores are needed to join the earlier
[geometry replay](GEOMETRY_STORAGE.md) to the subsequent
[numerical memory history](STORAGE_HISTORY.md) without a CAP-entry byte reset.

This is a component of that integration. FILE records, raw technology header
arrays and non-cache allocator metadata bytes still need their producers.
The production trailing-via guard remains enabled.

The subsequent [libio replay](LIBIO_STORAGE.md) now generates all selected
FILE/header records and relevant head/footer stores, matching every pre-free
buffer in all 130 original histories. The rectangular cache-table corruption
and the remaining integration described there still fail strict validation.
The later [shared cache replay](CACHE_STORAGE.md), with newly captured earlier
cache inputs, now matches the actual rectangular damaged walk in all 134 new
histories. The older incomplete-context strict audit remains required.

## Generation and transport

The production spectral table generator now optionally retains the complete
final FFT scratch array. Both implementations use their existing grid
transform and operation order. The compiled kernel adds a read-only export of
its scratch buffer; optional Python/JavaScript output buffers copy those
results. Axis transforms leave the grid scratch intact. Normal table/FFT
calls still return their usual outputs and do not retain diagnostic storage.

The binary cache stream follows `potential_cache.cpp`: the two dimensions,
frequency and raw technology records precede every pair's combined, X and Y
tables. The table data comes from the production spectral generator. Raw
technology header bytes that have not yet been ported remain **unknown**.
`file_buffer_storage.py` follows the successful fully buffered binary paths of
glibc 2.39's [`_IO_new_file_xsputn` and `_IO_file_xsgetn`](https://github.com/bminor/glibc/blob/glibc-2.39/libio/fileops.c),
including direct block transfers that bypass the stream buffer and underflow
fills that leave its unused tail intact. It does not substitute a zero header
or take final bytes from a native file. The complete selected final stream
buffers are known from those operations despite the unknown earlier header.

The copied glibc algorithm is distributed under LGPL-2.1-or-later, with source
and license attribution in the module. The browser's `reasitic.zip` includes
that Python source; the license is also shipped separately. This successful
path does not yet cover line buffering, backup areas,
short reads/writes, file errors or arbitrary FILE-state corruption.

## Independent native observations

`capture_prelude_storage_original.py` preserves all 65 existing input histories
in cold and warm states. At libc `free` entry it reads the complete original
allocation request of **every** block freed during that phase. It also retains
the complete driver-entry heap and the complete CAP-entry heap as independent
input and output observations. No inferior function, instruction result or
returned pointer is changed. The final heap is never used by the new buffer
producer or comparator to initialize execution.

The full capture SHA-256 is
`b36a0c4e32972ccbe60cd413712eba9b4ffb6488a4bcb4385f22840fe6e288eb`.
Its **1,430 pre-free buffers**, all initial/final heap regions, request scripts,
stdout, cache manifests, allocator observations and outcomes are retained.
Lossless deduplication represents whole heaps with exact 4096-byte pages and
whole pre-free buffers with SHA-256 keys. Nothing is selected by a later via
target or numerical result. The 176,755,132-byte uncompressed observation is
stored in a 4,402,247-byte fixture with 1,111 page values and 170 buffer values;
tests validate every key, size and region digest during reconstruction.

The source now matches, in packaged Pyodide/WebAssembly:

- **All 130 original cases**, with zero differences.
- **975 complete grid FFT workspaces**, including every packed metal pair
  generated in each of the 65 cold observations.
- **130 complete writer/reader stream buffers**.
- **4,526,080 byte-exact output bytes** across those workspaces and buffers.

The remaining 325 pre-free FILE/header blocks are retained in full for the
next porting step; no observed buffer is discarded. Their bytes are not claimed
as generated by this stage. Original full-command outcomes are also retained:
123 normal exits, six SIGABRT exits and one SIGSEGV exit. The observer stops
earlier at node entry or fault, independently of the plain command outcome.

Four added original observations cover 8×8 and 16×8 FFT grids in both cache
states. All **30 workspaces, four stream buffers and 27,904 bytes** match in
portable Python and packaged WebAssembly. The rectangular cold plain run
aborts after producing non-UTF8 text; the earlier read-only observer reaches
node input. The capture harness now uses UTF-8 `surrogateescape` for native/GDB
stdout, stderr and scattering-file text so every original byte survives JSON
storage. It does not replace undecodable bytes or drop that history.

Regressions alter an expected FFT word and remove the final output heap:
comparison fails on that word, while the independently generated value remains
unchanged. Separate unknown-header tests verify that unported bytes stay
unknown and unwritten tails retain their caller contents.

## Checks and remaining work

The mandatory `prestorage` suite runs both complete native comparisons and
provenance tests with the actual packaged compiled backend. All prior suites
remain required. Existing compiled checks still match 33 complete original
tables / 556,434 components, 1,728 regional/transfer calls, 88 coefficient
groups, 83 FFT/grid cases / 17,342 components and 20,014 hyperbolic cases.

```sh
PYTHONPATH=src python tools/capture_prelude_storage_original.py --debug-directory /tmp/debug/usr/lib/debug --reference /path/to/asitic-re --library-path /path/to/native-libraries --full-output /tmp/prelude-storage-full.json.gz
PYTHONPATH=src python tools/capture_prelude_storage_extended_original.py --debug-directory /tmp/debug/usr/lib/debug --reference /path/to/asitic-re --library-path /path/to/native-libraries
PYTHONPATH=src:tests python -m unittest test_prelude_storage_original -v
python tools/build_site.py
node tools/check_prelude_storage_original.mjs /path/to/pyodide.mjs /tmp/prelude-storage-audit.json /tmp/prelude-storage-extra-audit.json
```

The whole CAP-entry heap is captured to expose missing stores, not to repair
them. The subsequent libio stage now reproduces FILE construction/closure,
raw technology header copies and head/footer stores. Shared cache-table stores
are generated by the later cache replay; [allocator pointer stores](ALLOCATOR_STORES.md)
now cover bin/fastbin links. Remaining intervening stores are still required for
the complete byte history. Earlier process/scene
startup, secondary geometry groups, later command cleanup and the known
logarithm/cosine and JOIN/UNJOIN discrepancies also remain unfinished. Exact
buffer matches alone do not establish whole-program parity or authorize
deployment of this development branch.
